# 块编辑与发布模块

`Editor.tsx` 是后台与阅读页原地编辑共用的 React BlockNote 编辑器。只在客户端加载。支持原生斜线菜单/选择格式化、媒体块、自定义安全 embed、Markdown 导入导出、AI 选区改写、版本历史。

## 状态与协议

- 保存：POST 创建或带 `version` 的 PATCH，仅写草稿。
- 发布：先保存，再带最新 `version` 调用 publish；不把保存误称为发布。
- 冲突：409 保留本地输入；`post-merge.ts` 做字段三方比较，独立修改安全合并，同字段不同值必须二选一。正文按整体处理。加载前由 `local-recovery.ts` 持久保存副本，失败不替换输入。
- AI：只有已配置服务端凭据才请求；建议先展示，用户确认后应用，不伪造成功。
- 离开：返回写作台、原地返回阅读和当前标签的同源链接先显示站内未保存对话框。取消保留输入，明确丢弃只放行这一次导航，不再叠加浏览器离站弹窗。保存事务中阻止跳转。
- 浏览器刷新、关闭标签、地址栏跳转和跨文档历史后退仍由原生 beforeunload 兜底，不能为了消除提示而静默丢失草稿。下载、新标签打开、页内锚点不触发站内离开确认。

## 测试

`tests/e2e/author-flow.spec.ts` 先设计真实 BlockNote 编辑、草稿与发布快照隔离、同编辑器原地修改和冲突用例。需要本地隔离作者身份与 Playwright 浏览器；运行情况以最终验证记录为准。

## 已补回归

保存事务使用 `editor-state.ts` 的编辑序号：响应只确认已提交快照，不覆盖等待期间输入的标题或链接，不误清新的未保存状态。发布沿用该快照序号并锁住整个保存/发布事务。Markdown 导入按实际内容判断，不以块数量判断空白。原地发布后返回阅读会重新请求服务端最新发布快照。

`tests/editor-state.test.ts` 覆盖延迟保存、发布时后续输入、单段/附件/嵌套导入覆盖条件；`tests/e2e/editor-regressions.spec.ts` 提供相应真实界面回归、发布返回、撤回发布用例。作者 E2E 必须有显式测试身份，缺少身份直接失败而不跳过。

阅读页作者入口使用轻量 SSR + client:load，不再为了显示按钮静态加载 BlockNote；主动打开后才通过 React lazy 加载完整编辑器，等待时有明确状态。编辑页本身仍为 client:only，以避免富文本浏览器依赖进入服务端执行。移动端 viewport 声明 resizes-content，键盘行为仍需真机验收。

`editor-navigation.ts` 将未保存确认与一次性卸载放行集中管理。`tests/editor-navigation.test.ts` 覆盖取消、确认、重复点击、保存中及恢复；`tests/e2e/editor-navigation.spec.ts` 覆盖返回按钮、侧栏链接和刷新保护，实际浏览器运行记录以交付说明为准。

## 交互链路竞态回归

载入最新版本、历史恢复和 Markdown 文件读取都捕获请求开始时的编辑序号。响应迟到且期间有新输入时，不替换本地正文/标题，不清 dirty；历史恢复已写入服务器时，仅跟进新的 CAS 版本。保存、发布、恢复、载入、导入、撤下发布与 AI 请求共用同步事务锁，避免同一事件批次重复写入。发布过程的可见性/密码选择固定，不能显示已经切换、实际仍发布旧选项。

AI 面板关闭/重开使旧请求的建议失效；改变处理动作会清除旧建议，禁止把旧操作的结果应用到新目标。单测见 `editor-replacement.test.ts`、`ai-request-state.test.ts`；真实 DOM 点击由 `tests/ui/editor-clicks.test.tsx` 覆盖，BlockNote 和网络在该层为隔离替身，不等于真实供应商或浏览器排版验收。

## 媒体上传失败提示

BlockNote 上传面板会吞掉 `uploadFile` 抛出的异常、只显示通用“上传失败”，块以空 url 留在正文里。`uploadFile` 因此先用共享的 `mediaUploadProblem()`（来自 `src/modules/config` 的 `uploadProblem`，与服务端同一函数、同一份设置页配置：各类型上限默认 25 MB、可禁用类型）做上传前检查：拒绝时写 `editor.upload_rejected` 日志（只含 reason/mime/size，不含文件名）并在编辑器提示栏显示中文原因；服务端拒绝或网络失败由 `api()` 记录 `api.request_failed` / `api.network_failed`，编辑器显示“上传失败：<原因>”。视频支持 MP4 / WebM / MOV（文案由 `uploadHint()` 按当前配置生成），MKV 等需先转码。

## 嵌入与视频块文案

工具栏“嵌入”弹窗和 BlockNote 媒体面板（“从电脑上传 / 粘贴链接”）的支持清单、拒绝提示都来自 [src/modules/embed](../../modules/embed/README.md)。弹窗用 `parseEmbed` 实时校验，插入的是规范化后的链接。b23.tv 短链会提示作者粘贴完整地址。实时预览不写日志，点“插入”被拒绝时才写日志。

## 保存 / 发布失败必须可见（2026-10-27）

曾经的事故：服务端以 422 拒绝了视频块里的 X 嵌入代码，但英文错误只显示在页面顶部，被仍然打开的发布弹窗遮住，作者以为“点了没反应”。现在的约定：

- 所有失败都经 `fail(action, error)`：`errors.ts` 的 `describeEditorError()` 生成“保存失败：/发布失败：……”中文提示（服务端中文原因原样使用，英文错误码逐个翻译，未知错误保留原文和错误码），非 `ApiError` 另记 `clientCaught` 日志；
- 错误同时显示在页面顶部（自动滚动到可见）**和**当前打开的弹窗里（发布、AI、历史版本）；
- 保存前先用 `src/modules/content-check` 预检，有问题直接提示“第 N 个视频块……”、高亮该块，不发请求，并记 `editor.save_blocked`；
- 未登录时保存不再静默返回，给出提示并记日志；
- 只有版本冲突才显示“载入最新版本”，链接标识冲突 / 文章已删除虽然也是 409，但给各自的中文原因；
- 视频块建议条（`.editor-video-advice`）：X 动态 → “改为嵌入块”；认不出的嵌入代码 → “移除这个视频块”；YouTube / Bilibili 嵌入代码自动换成规范链接；
- 工具栏“嵌入”弹窗接受官方嵌入代码，显示“已从嵌入代码中识别出 … 链接”，插入规范链接。

回归：`tests/ui/editor-save-errors.test.tsx`、`tests/unit/editor-errors.test.ts`。

## 并发编辑与正文二选一（2026-11-01）

基准是编辑器已加载/已保存的完整文章，不能只把服务器最新版本号贴给旧内容。媒体删除响应新增 `clearedCovers[].previousVersion`；仅清理前版本等于本地基准、清理后恰好 +1、且当前无保存事务时才跟进。旧服务端缺字段、跳版本、并发保存期间的回调均不推进基准。回调读取最新表单，删除旧图不会清掉之后新选的封面。

普通保存遇到 `VERSION_CONFLICT`：读取最新文章，以基准、本地、服务器三份数据比较。可独立合并标题、摘要、标签、链接；分类名称/id作为一组，封面URL/比例/焦点/缩放作为一组，正文作为一组。只在双方未同时改变同字段，或改成相同值时自动合并。最多自动提交一次，使用读取到的服务器版本做原子CAS；再冲突则重新读取、要求确认。不自动修改发布状态或发布快照。

真正冲突的站内弹窗只有两种处理：

- **保留我的版本**：采用本地的所有已列出冲突字段；服务器不冲突的独立修改仍保留。正文冲突时采用整篇本地正文。提交仍带弹窗对应服务器版本；服务器又更新就重新提示，绝不force。弹窗期间新出现的字段冲突先重新展示。
- **保留我的副本，再加载最新版**：重新读取服务器，先保存完整本地副本并读回确认，随后以服务器最新文章替换所有字段，不混入本地内容。写副本失败或读取期间又输入，当前内容保持。尚未发布的本地修改不会因为这个动作自动发布。

关闭弹窗仅隐藏选择，本地输入与基准保留；顶部“检查版本冲突”可重新打开。合并/选择提交期间若仍有输入，不把新版本号套给未经比较的新输入，下次重新检查。BlockNote首次填充默认属性的文档作为本地基准，避免把初始化当作正文编辑。

### 副本找回与限制

进入**同一网站、同一浏览器的该文章编辑页 → 顶部“本地副本” → 选择本地副本 → “恢复这份副本到编辑器”**。恢复仅放回编辑器，不直接写服务器；保存仍检查版本。已有未保存输入会先另存副本。副本保存基准及本地完整文章，协议由共享 `postSchema` 派生，不存令牌、密码输入或模型凭据。

副本保存在浏览器localStorage（每份独立键，不覆盖旧副本），不是服务器备份，不跨设备或浏览器同步。清理网站数据、浏览器隐私模式结束、存储损坏会使其不可用；配额或权限拒绝会阻止加载。文章仅对当前已认证编辑器显示副本入口；副本本身未加密，退出登录不会清除，本机共用浏览器的人可能从网站存储读取，所以私人设备仍需自行保护。没有新增后台同步或生产数据迁移。
