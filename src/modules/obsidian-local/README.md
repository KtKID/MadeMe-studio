# 浏览器本地 Obsidian 保存

本模块是**网站当前稿 → 本机 Markdown 和附件**的主动保存适配器，不是后台同步服务，也不改变现有 Obsidian → 网站发布插件。没有新增后端 API、令牌或守护进程。

## 使用

1. 设置 → **同步 Obsidian** → 添加预设，浏览选择 vault 根目录或其授权父目录。名称可自定，默认文章子目录为 `笔记`、图片规则为 `../asset`。
2. 预设及真实目录句柄只存当前浏览器 IndexedDB。手填绝对路径不能授权；换浏览器/清数据需重选。不向后端上传目录句柄、路径或本地正文。
3. 在文章编辑器点 **保存到 Obsidian**，选择预设或临时位置，可浏览根目录内文章子目录。保存取点击当时的标题、正文、图片与封面快照；未保存的网站草稿也可导出，不自动发布。
4. 目录不存在时明确选择创建，或从系统 `documents` 位置重新选择；权限失效必须重新授权，取消即停止。
5. 本地保存完成后保留原有“在 Obsidian 中打开”入口，不增加登记名/ID或根目录确认步骤。这个入口仅沿已授权根到保存文章的目录祖先链检查 `.obsidian`，使用离文章最近的候选仓库名称及仓库相对路径调用应用；本地保存成功不代表 Obsidian 一定能找到并打开仓库。

文章祖先链内找不到 `.obsidian` 时仍可保存，但不生成猜测的打开链接。最近的配置目录不等于已验证应用登记；残留或自定义配置目录可能无法自动定位。浏览器不支持 File System Access 时仅提供普通 Markdown 下载，图片仍为网站链接，**不是完整离线导出**。外图受 CORS 限制，取图失败会停止完整保存，不绕过权限。

## 文件与身份

- 共享 [导出准备模块](../local-export/README.md) 负责快照、Markdown 和媒体清单；这里不重新实现文章权限、上传或媒体 ID。
- `contracts.ts`：Zod 本地预设协议；历史 `obsidianVault` / `vaultRootConfirmed` 仅作为可选兼容字段保留，不显示、不要求填写、不作为打开前置条件，新预设不自动加入它们。`presets.ts`：IndexedDB 事务、用户手势目录选择、vault 检测。
- `save.ts`：路径规范化、文件名安全处理、完整媒体下载、冲突检测和落盘。所有相对规则必须留在授权根内。
- 根目录 `.mademe-export.json` 记录文章 ID → 路径、媒体 ID → 路径及已写内容指纹。指纹只用于发现本地修改，不替换现有媒体 ID、不用于自研哈希命名。
- 原媒体名优先；缺少块原名时读取现有下载 API 的 Content-Disposition。陌生同名文件不会因为名字相同而认定同一资源；冲突追加稳定 ID 后缀，仍碰撞再编号。文件名限制 UTF-8 字节，并处理常见系统禁用字符。
- 再保存同篇复用记录；选择不同文章目录会在新位置保存并保留旧文件。改标题不强制重命名既有已跟踪路径。
- 手动删除已导出文章或图片后，再保存以磁盘实际状态为准重建缺失文件，不把历史清单当作文件仍存在；权限/IO 错误不会当作缺失。创建前发现陌生同名文件仍停止。见 [删除后重存报告](../../../reports/2026-10-28-obsidian-deleted-file-save.md)。
- 本地文章已修改时先提示另存副本或明确覆盖；确认后下载期间若再次改动，提交前复核仍会阻止覆盖。旧图片被本地修改则新写另一文件，不覆盖它。
- 全部附件先下载成功，再写附件，最后以 File System Access writable close 提交正文，最后更新清单。不是跨文件系统事务：磁盘失败可能留下新附件；正文成功后清单失败也会报告失败，重试可能要求另存/确认。不会把已失败的半成品谎报为完整同步。
- 同站浏览器 Web Locks 串行化多标签保存，本页也全局排队；浏览器没有 Web Locks 时拒绝目录写入并提示普通下载。外部程序在最终检查与文件提交间的极短竞态无法提供操作系统级 CAS 保证；不同来源/浏览器同时操作同一目录不在锁范围内。

Markdown 转换本身有损；特殊块/样式需核对。平台视频和嵌入仅保留原链接，不下载平台内容。保存没有改变网站原稿。

- `tests/obsidian-presets.test.ts`：授权能力、取消、路径拒绝和 IndexedDB 真正事务完成/失败。
- `tests/obsidian-filesystem.test.ts`：隔离 mkdtemp 真实文件读写，验证字节、重复保存、本地改稿和长中文同名附件；不是原生浏览器授权验收。
- `tests/obsidian-save.test.ts`：内存目录的完整保存、图片失败不改旧稿、本地冲突、同名媒体、下载期间新修改。

## 界面设计契约

设置与保存弹窗复用现有 `.button` / `.primary` / `.small`、`.button-group`、`.form-stack`、`.form-grid`、`.config-card`、`.form-hint` 及共享 Modal / `.modal-actions`。不使用裸按钮或浏览器默认 fieldset 边框，不定义本模块独立主题。busy 状态仍禁用输入与操作。样式接线测试与真实截图验收分开记录，详见 [样式修复报告](../../../reports/2026-10-28-obsidian-ui-style-consistency.md)。

配置目录的系统选择器仅请求读取；保存/编辑预设只写 IndexedDB，不申请 vault 写权限。实际点击保存文章时才查询写权限：已授权直接继续、需询问时申请一次、已拒绝则停止并提示调整权限。浏览器必要的原生读取/写入授权仍可能出现，站内确认框不能替代或绕过它。

保存本地预设先显示博客共享 Modal“是否保存此预设？”，确认摘要后才写 IndexedDB；取消保留编辑输入，失败留在弹窗可重试。它只是业务配置确认，不能替代真正保存文章时浏览器必要的文件写入授权。


## Obsidian 打开边界

`open.ts` 保留相对路径校验与参数编码，恢复原有 best-effort URI：已授权目录 `name` + 已保存相对路径。仅沿用现有 `.obsidian` 检测，不扫描更多位置，不移动文件，不猜绝对路径或读取应用登记表。浏览器句柄只暴露名称及授权树内访问，不能可靠验证 Obsidian 实际登记的仓库名称。

因此原 `Vault not found` 根问题尚未解决，恢复入口不是修复成功声明。旧版擅加的登记身份输入、根确认 checkbox、提示和限制已按用户要求撤回，不能再要求用户为此完成额外配置。官方协议参考：[Obsidian URI](https://obsidian.md/help/uri)。

编辑器入口的工具栏样式只作用于直属按钮；本模块保存 Modal 通过 portal 挂至 body，避免快捷栏的后代按钮样式污染弹窗。共享 Modal 本身及其它弹窗不改。回归包含真实全量 CSS 的 cascade、按钮 padding/字号/hover/disabled/focus、主题 token、焦点恢复和 SSR；jsdom状态模拟不代替真实浏览器截图。

打开目标定位仅检查保存路径祖先，不扫描兄弟目录、不读正文、不读取本机应用登记；读权限/IO异常不吞掉，已保存文件不回滚或搬动。见 [真实 URI 根层级修复](../../../reports/2026-10-28-obsidian-open-root-resolution.md)。
