# 已保存但未重新发布的内容状态

`hasUnpublishedChanges` 与 `publishedVisibility` 是服务端只读派生字段，Zod 协议位于 `contracts.ts`。编辑器未保存的 dirty 是另一种状态：本模块只比较已经持久化的草稿和发布快照，不比较输入框内尚未保存的改动。

## 判定
- 没有发布快照：没有“有新修改”。有快照：比较标题、slug、摘要、正文块、封面、标签、类型、可见性与置顶；任何实际差异提示“有新修改”。保存不覆盖发布快照，线上原可见性仍由 `publishedVisibility` 表示。
- 同内容保存、还原到发布版本：不提示；重新发布用当前草稿更新快照后清除提示。
- 对象键顺序、版本号、更新时间、删除时间和正文块的编辑定位 ID 不算内容差异。正文已知默认文字颜色/背景色/左对齐、空样式和空子块数组归一化；文字、样式、图片 URL/说明及其他未知块属性仍参与比较，不能把不认识的内容默默忽略。
- 类型通过现有稳定 ID / 历史名称解析器统一归属。同一类型更名不误报；无归属旧分类仍比较原文字，不迁移或删除旧数据。

## 数据与安全边界
返回状态是草稿副本的附加字段，绝不写入文章 JSON、发布快照或历史版本。创建/PATCH 协议不接受这些字段。作者及具备文章读取权限的客户端可取得状态；读者接口继续只返回发布快照，不暴露未发布变化。列表在服务器读取正文完成语义比较，响应仍只包含摘要字段，不传正文、发布快照或密码摘要；这是服务器读取成本增加，不是正文下发。

密码摘要采用随机盐，本模块不通过摘要比较推断密码明文是否改变，避免相同密码重新输入误报。本轮提示针对内容和发布可见性；仅密码变更不触发“有新修改”。不扩展发布流程，不自动重新发布。解析依据当前类型目录；并发目录更名与读取之间仍可能存在短暂不同视图，下次读取会按最新目录统一解析。

测试：`tests/backend/publication-status.test.ts` 使用真实 SQLite 和 HTTP API，覆盖发布/保存/恢复/重新发布、公开字段、块 ID 默认值、类型更名/别名、未授权读取与只读字段注入；`studio-loading.test.ts` 验证服务器比较而不把正文传到列表。
