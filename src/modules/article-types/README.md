# 文章类型

稳定 ID 与显示名称分离的轻量类型目录，不是标签、层级分类或展示模式配置。旧文章 `category` 文本和标签保留；新文章可使用 `categoryId` 关联类型。预设 AI、感悟，仅旧设置缺少字段时补默认，明确空列表不会恢复默认。

## 协议与存储
- `contracts.ts` 是 Zod 单一来源：类型、名称、命令与响应。名称经 NFC/去空格后保存，大小写不敏感防重，最多 100 项。
- 类型列表保存在现有 settings JSON 的 `articleTypes`；无需数据库迁移或分类表。类型 ID 创建时由服务端生成，重命名不会变化。更名前名称记录为隐藏的 `legacyNames`，用于匹配旧文章自由分类；跨类型名称/历史别名不能重复，不生成额外首页选项。历史名称最多 100 项，超限明确拒绝，避免无限增长。
- 普通 settings PATCH 禁止传 `articleTypes`，专用命令不能覆盖其它设置。
- `GET /api/article-types` 返回公开类型列表；`POST` 仅作者身份可用，并经过现有同源校验。命令为 `create`、`rename`、`delete`；新增响应含 `selectedId`，用于新增后自动选中。
- 写入按原始 settings JSON 做 compare-and-swap，冲突最多重试 4 次再明确返回 409。并发新增不丢其它类型/设置，同名竞争只成功一个。不提供无限重试。

## 文章兼容
- 提交有效 `categoryId` 时，服务端以目录内名称覆盖提交的 `category`，防止 ID/名称不一致。
- 删除类型会检查全部草稿、已发布快照和回收站：ID 引用或无 ID 的当前/历史名称引用均拒绝删除，并提示先调整文章。不会删除或批量迁移文章。对历史上已存在的缺失类型 ID，原文章仍可保留原文本编辑；新文章不能冒用未知 ID。
- 没有 ID 的旧客户端继续保存原 `category` 文本；旧客户端显式改已有文章分类文字时解除旧 ID，避免错误归类，仅改正文不会解除关联。清空 ID 表示明确不分类。
- 展示层用配置名称解析 ID，旧文本作为兼容回退；标签字段独立。

测试：`tests/backend/article-types.test.ts` 用真实 SQLite 执行 CAS SQL，覆盖默认/重复、鉴权、跨站、并发和文章旧数据。UI 与首页行为由父集成回归覆盖。

## 写入边界与 UI
- 删除引用检查附在 CAS 写 SQL 上；文章 INSERT/UPDATE 同时校验新 ID 仍存在，阻止“先校验类型、类型被删除、随后写入文章”的明显竞态，失败不生成虚假 revision。旧文章已有缺失 ID 未改变时仍兼容编辑。
- 旧客户端仍可写任意自由分类文字，这是兼容入口，不等于创建类型目录；不能保证自由文字都对应类型。手工修改数据库不属于 API 原子保护范围。
- `TypeSelector` 和 `TypeNameForm` 共用选择/新增/改名交互，新增成功后自动选中；`TypeSettings` 删除使用站内 Modal，服务端拒绝删除已用类型。
- 客户端同页事件同步，页面重新获得焦点后刷新跨页数据；GET 迟到不会覆盖写入广播，加载失败保留列表并可重试。不宣称跨设备实时同步。

同页类型写请求串行排队，单次失败不会阻塞后续操作；关闭新增表单不撤回已提交或排队的保存，但不将迟到成功结果回填已取消的文章选择。设置页新增/修改即时保存，历史别名是内部兼容数据，无额外配置控件。

## 同主题类型下拉
首页、后台筛选与编辑器共用 `TypeDropdown`，不再打开操作系统原生 select 菜单；类型数据和新增协议不变。按钮使用 combobox/listbox 语义，方向键移动、Enter/空格选择、Escape 取消，Tab 关闭后继续正常焦点顺序，外点关闭不抢焦点。选中后关闭并将焦点还给入口。浮层通过 portal 挂到 body，继承站点明暗/皮肤 token；按可用视口空间向上或向下展开，长列表内滚动，页面滚动/尺寸变化重新定位。水合前入口禁用，避免可点击却无反馈。
