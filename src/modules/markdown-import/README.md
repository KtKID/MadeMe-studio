# Markdown 与附件导入

本模块共用网页/Obsidian 的引用识别、路径边界、去重、上传后地址替换和媒体类型转换。不是 Markdown 发布接口，也不读取生产数据。协议仍由 `src/shared/contracts.ts` 的 Zod schema 定义。

- `attachments.ts`：使用 `mdast-util-from-markdown` 2.0.2 的源码位置识别标准图片与引用式图片，补充 Obsidian `![[附件路径|说明或尺寸]]`。代码块、行内代码和转义不触发附件访问；HTML 媒体标签明确报错，不执行 HTML。
- `RepositoryImportButton.tsx` / `repository-import.ts`：正常导入只使用[独立Obsidian仓库连接](../obsidian-repository/README.md)，不读取/迁移笔记导出预设。原生 FileHandle 经连接根 resolve 确认位置，仅自动读取本篇引用附件；连接更换/清除使旧操作失效。
- `ImportDialog.tsx`：逐项显示名称、类型、来源、仓库相对路径和状态。仓库模式自动匹配，缺失/歧义安全停止，不要求逐个补选。上传后及应用前校验连接版本，确认期间新增编辑不覆盖。
- 未连接或浏览器不支持原生句柄时，给独立设置入口；单文件降级明确不自动读本地附件，仅此降级保留手动选择，不猜旧预设。
- `selection.ts`：显式文件选择累加；真正引用的同名同大小文件按字节去重，保留原 File 身份与上传缓存，同名异图不覆盖而明确提示。未引用文件不为去重读取内容、不上传。移除／替换只影响指定项，排队处理连续选择，取消或新来源使旧回调失效。
- `import-dialog.css`：仅导入窗口的布局，颜色和字号继承站点主题；隐藏原生 file input，由共用 `.button` 与 Modal 操作区触发。操作系统的文件选择窗口仍由浏览器负责。
- `blocks.ts`：原服务器保守 Markdown 转块逻辑的同构实现；`src/server/content/markdown.ts` 仅再导出。旧客户端若直接提交未上传的相对图片或 wiki 嵌入，返回 422，避免静默变成文字。
- Obsidian 入口见 [插件 README](../../../integrations/obsidian-publisher/README.md)；请求安全与 scope 见 [共享客户端](../../../integrations/shared/README.md)。

## 路径与权限

文件夹/vault 模式以所选根目录为边界，标准路径相对笔记所在目录；wiki 额外接受根相对路径或唯一文件名。拒绝越界、绝对路径、反斜线、危险协议。标准 Markdown URL 解码一次再检查；wiki 和真实目录名按字面匹配，不做百分号解码：`![[100%25.png]]` 指向字面文件 `100%25.png`，`![图](100%25.png)` 才指向 `100%.png`。支持中文、空格、百分号和 Unicode NFC。多个同名候选明确报错，不猜第一项。网页多文件模式仅在用户显式选择的 File 集合里按唯一文件名匹配，相对路径本身不能授予任意磁盘访问权。

正常仓库路径不按同名或正文猜文档：只读取所选原生 FileHandle，根 resolve 必须确认在独立连接的仓库内。标准相对路径直接查找；裸 wiki 文件名必要时遍历有界的目录元数据确认唯一性，不读取其它笔记正文。目录元数据遍历上限为配置 `MAX_REPOSITORY_IMPORT_ENTRIES`。上传前再次核对句柄仍在根内、大小与修改时间，文件变化停止。

单文件降级的辅助文件夹匹配才读取已选 Markdown 的同名候选来核对内容，其它笔记不读取、不上传；只有正文实际引用的附件会上传。Obsidian 只枚举 vault 文件路径/大小/修改时间元数据用于解析，不读其它笔记正文，逐个读取→上传引用附件，不预加载所有二进制。附件读取前后核对大小与修改时间。

已有 HTTPS 和 `/api/files/<id>` 嵌入不重复上传，不让服务器拉取远程 URL。Token 请求固定为配置原点、禁 Cookie/重定向；附件需要 `media:write`，草稿需要 `posts:write`。不自动申请或扩大 Token 权限。

网页只选一个纯Markdown文件不能取得旁边本地图片的字节；缺失项会列明并要求最少的补充选择，不声称无授权全自动读取磁盘。文本中的可用HTTPS媒体地址直接保留；嵌入且有明确mp4/webm/mov后缀的地址按既有规则转视频，普通文字超链接仍是链接。无后缀的远程媒体不由服务器探测、不保证可识别所有视频站点。Obsidian插件有当前vault文件能力，仍可按实际引用自动读取附件，网页使用独立同源仓库连接，不新增本地服务或写权限。正式博客和独立Site不同origin，连接不能继承。笔记导出预设原数据与写入行为保持，删除它们不影响导入连接。

需求与验收见 [独立仓库TODO](../../../docs/task/task-obsidian-repository-import.md)。真实浏览器验证使用Settings独立设置、真实IDB与native OPFS句柄，再走正常导入上传保存。picker返回受控，不能当真实外部OS目录授权成功；原生Obsidian宿主未运行。

## 支持边界

| 输入                                                                    | 行为                                                                                                       |
| ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `![图](../assets/photo.png)`、`![图](<../assets/中文 空格.png>)`、`%20` | 选择附件后上传并替换为本站 URL；标准 Markdown 的空格用尖括号或 URL 编码                                    |
| `![图][ref]` + 链接定义、`![[assets/图.png]]`                           | 同样解析；同一 File 多次引用只传一次                                                                       |
| PNG/JPEG/WebP/AVIF                                                      | 走现有媒体验证与图像处理；本模块不改变压缩/鉴权策略                                                        |
| GIF                                                                     | 按原件上传，保留动画；不转成静态 WebP                                                                      |
| `![[clip.mp4]]` 或 `![视频](clip.mp4)`                                  | 根据上传响应 MIME 建立 video 块，而非把无扩展名文件 URL 当图片                                             |
| MOV / WebM                                                              | 媒体接口原件保留；MOV 不是所有编码都能播放。已测 H.264 MOV 的 Chromium 播放，未保证 HEVC/ProRes/其它浏览器 |
| MP3/WAV/OGG/M4A、PDF 嵌入                                               | MIME 分别转 audio/file 块；本轮未做全浏览器/全部格式播放验收                                               |
| SVG、HTML 媒体标签、MKV、其它笔记嵌入                                   | 明确拒绝，不当作可播放媒体，不上传链接笔记                                                                 |
| 链接包裹图片，如 `[![图](x.png)](链接)`                                 | 暂不支持；在上传前明确拒绝，保留原文，避免把外层链接拆成乱码；标准、引用式和 wiki 嵌入同样处理             |
| 普通 `[附件](路径)` 文本链接、笔记双链、frontmatter/天气                | 本轮不新增这些字段或链接的转换；附件自动化针对 `![]()` / `![[ ]]` 嵌入                                     |

新上传附件的类型由真实上传响应确认。已有无扩展名本站 URL 不重新探测私有媒体，也不能仅凭 URL 推断它是视频；这类旧内容沿用 Markdown 原有块类型，视频应通过附件导入或现有媒体选择入口插入。

媒体在 BlockNote/保守解析器中以独立块呈现；行内媒体会分成相邻文字段和媒体块，不承诺完整保留复杂嵌套排版。插件继续使用已有保守 Markdown 转块能力，网页继续使用 BlockNote 解析器；附件处理规则共用，不声称两者 Markdown 排版能力完全相同。

## 失败、取消与资源限制

所有引用完成路径、格式与硬大小预检后才开始上传；服务器仍按真实字节、账户上传设置和大小限制做最终校验，不放宽 URL 校验。单次最多 128 处媒体引用，单文件沿用 50 MB 硬上限及服务端更小配置。插件大静态图超出服务端解码限制会明确失败，不声称有网页的 Canvas 预缩小能力。

失败、关闭和取消均保留编辑器当前正文或插件的原笔记；导入等待期间新输入不会被旧 Markdown 覆盖。不把部分上传当成功导入，不自动保存/发布。已到达媒体库的附件不会随取消被删除，同一次预览的重试复用已完成上传；重新选择文件/关闭后新开属于新操作。网络超时可能已到达服务器，检查媒体库/Studio 后再重试；文章创建不具有幂等键，不自动重试 POST。

媒体上传在集成客户端中使用独立10分钟等待预算，普通JSON写入仍为20秒；用户取消立即传递，不要求新版 AbortSignal 静态方法。网页上传仍使用原有请求链，不新增该固定时限。更长预算不保证所有网络/代理都能完成传输，超时仍需核对实际结果。

网页每次文件选择有独立来源序号：切换/关闭立即使旧读取和上传失效，旧回调不能应用正文、关闭新窗口或覆盖新错误。引用分析和预检按文档/选择内容缓存，上传进度更新不重新解析；代码/链接区间合并后单向扫描，真实引用达到上限立即拒绝，而非扫描完全部 wiki 再拒绝。

API兼容边界：不新增或改变 Post/Media Zod字段。未定义的引用式链接仍按文字保留；非媒体HTML仍为不可执行的文字。HTML媒体标签、链接包裹图片以及未上传本地媒体明确422，CLI/旧客户端应拆出图片或完成附件上传后重试，不能依赖旧解析器对这些结构的丢失式转换。

## 验证

兼容性发布说明：防止静默丢媒体的422是破坏性行为变更，不保证所有旧Markdown无损兼容。未上传的本地媒体、HTML媒体、链接包图与非HTTPS远程媒体会拒绝，不能靠放宽URL校验或服务器代抓解决。仓库内CLI和Chrome剪藏仍调用 `createDraft`：CLI不上传附件；剪藏生成器会转义选区图片语法，但用户手改的Markdown仍受相同限制。Obsidian已走 `createDraftWithAttachments`。外部生产自动化未盘点，不能保证没有旧调用方，部署前应核对并迁移输入。

实际CommonMark解析回归证明：未定义的 `![a][missing]`、`![missing][]`、`![missing]` 都是文字，不产生 `imageReference`，有定义时才产生该节点。缺definition检查保留作不完整AST防御，不表示普通缺定义输入必然422。网页/插件准备附件时统一去BOM、CRLF/CR转LF，源码区间在规范化后计算。

`npm run test:e2e:markdown` 要求先 `npm run build`，启动全新临时本地 Worker/D1/R2；`CHROMIUM_PATH` 可指定已安装 Chromium。合成样本在 `tests/fixtures/markdown-media`，不使用用户笔记或生产凭据。测试涵盖文件夹选择、真实媒体 HTTP、草稿保存刷新、GIF 两帧与实际画面变化、H.264 MP4/MOV 播放，以及缺文件、网络失败、取消、重复点击和新输入。共享客户端是真实 API 测试；不等于原生 Obsidian 应用端到端。
