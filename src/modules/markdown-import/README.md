# Markdown 与附件导入

本模块共用网页/Obsidian 的引用识别、路径边界、去重、上传后地址替换和媒体类型转换。不是 Markdown 发布接口，也不读取生产数据。协议仍由 `src/shared/contracts.ts` 的 Zod schema 定义。

- `attachments.ts`：使用 `mdast-util-from-markdown` 2.0.2 的源码位置识别标准图片与引用式图片，补充 Obsidian `![[附件路径|说明或尺寸]]`。代码块、行内代码和转义不触发附件访问；HTML 媒体标签明确报错，不执行 HTML。
- `ImportDialog.tsx`：网页先选择 `.md`，再明确补选附件文件或共同上级文件夹；全部上传/转换成功且编辑时钟仍匹配才替换正文。成功导入不等于已保存或已发布。
- `blocks.ts`：原服务器保守 Markdown 转块逻辑的同构实现；`src/server/content/markdown.ts` 仅再导出。旧客户端若直接提交未上传的相对图片或 wiki 嵌入，返回 422，避免静默变成文字。
- Obsidian 入口见 [插件 README](../../../integrations/obsidian-publisher/README.md)；请求安全与 scope 见 [共享客户端](../../../integrations/shared/README.md)。

## 路径与权限

文件夹/vault 模式以所选根目录为边界，标准路径相对笔记所在目录；wiki 额外接受根相对路径或唯一文件名。拒绝越界、绝对路径、反斜线、危险协议；先解码引用的 URL 编码再检查，真实文件名不二次解码，支持中文、空格、百分号和 Unicode NFC。多个同名候选明确报错，不猜第一项。网页多文件模式仅在用户显式选择的 File 集合里按唯一文件名匹配，相对路径本身不能授予任意磁盘访问权。

文件夹只读取已选 Markdown 的同名候选来核对内容，其它笔记不读取、不上传；目录中只有正文实际引用的附件会上传。Obsidian 只枚举 vault 文件路径/大小/修改时间元数据用于解析，不读其它笔记正文，逐个读取→上传引用附件，不预加载所有二进制。附件读取前后核对大小与修改时间。

已有 HTTPS 和 `/api/files/<id>` 嵌入不重复上传，不让服务器拉取远程 URL。Token 请求固定为配置原点、禁 Cookie/重定向；附件需要 `media:write`，草稿需要 `posts:write`。不自动申请或扩大 Token 权限。

## 支持边界

| 输入 | 行为 |
|---|---|
| `![图](../assets/photo.png)`、`![图](<../assets/中文 空格.png>)`、`%20` | 选择附件后上传并替换为本站 URL；标准 Markdown 的空格用尖括号或 URL 编码 |
| `![图][ref]` + 链接定义、`![[assets/图.png]]` | 同样解析；同一 File 多次引用只传一次 |
| PNG/JPEG/WebP/AVIF | 走现有媒体验证与图像处理；本模块不改变压缩/鉴权策略 |
| GIF | 按原件上传，保留动画；不转成静态 WebP |
| `![[clip.mp4]]` 或 `![视频](clip.mp4)` | 根据上传响应 MIME 建立 video 块，而非把无扩展名文件 URL 当图片 |
| MOV / WebM | 媒体接口原件保留；MOV 不是所有编码都能播放。已测 H.264 MOV 的 Chromium 播放，未保证 HEVC/ProRes/其它浏览器 |
| MP3/WAV/OGG/M4A、PDF 嵌入 | MIME 分别转 audio/file 块；本轮未做全浏览器/全部格式播放验收 |
| SVG、HTML 媒体标签、MKV、其它笔记嵌入 | 明确拒绝，不当作可播放媒体，不上传链接笔记 |
| 普通 `[附件](路径)` 文本链接、笔记双链、frontmatter/天气 | 本轮不新增这些字段或链接的转换；附件自动化针对 `![]()` / `![[ ]]` 嵌入 |

新上传附件的类型由真实上传响应确认。已有无扩展名本站 URL 不重新探测私有媒体，也不能仅凭 URL 推断它是视频；这类旧内容沿用 Markdown 原有块类型，视频应通过附件导入或现有媒体选择入口插入。

媒体在 BlockNote/保守解析器中以独立块呈现；行内媒体会分成相邻文字段和媒体块，不承诺完整保留复杂嵌套排版。插件继续使用已有保守 Markdown 转块能力，网页继续使用 BlockNote 解析器；附件处理规则共用，不声称两者 Markdown 排版能力完全相同。

## 失败、取消与资源限制

所有引用完成路径、格式与硬大小预检后才开始上传；服务器仍按真实字节、账户上传设置和大小限制做最终校验，不放宽 URL 校验。单次最多 128 处媒体引用，单文件沿用 50 MB 硬上限及服务端更小配置。插件大静态图超出服务端解码限制会明确失败，不声称有网页的 Canvas 预缩小能力。

失败、关闭和取消均保留编辑器当前正文或插件的原笔记；导入等待期间新输入不会被旧 Markdown 覆盖。不把部分上传当成功导入，不自动保存/发布。已到达媒体库的附件不会随取消被删除，同一次预览的重试复用已完成上传；重新选择文件/关闭后新开属于新操作。网络超时可能已到达服务器，检查媒体库/Studio 后再重试；文章创建不具有幂等键，不自动重试 POST。

## 验证

`npm run test:e2e:markdown` 要求先 `npm run build`，启动全新临时本地 Worker/D1/R2；`CHROMIUM_PATH` 可指定已安装 Chromium。合成样本在 `tests/fixtures/markdown-media`，不使用用户笔记或生产凭据。测试涵盖文件夹选择、真实媒体 HTTP、草稿保存刷新、GIF 两帧与实际画面变化、H.264 MP4/MOV 播放，以及缺文件、网络失败、取消、重复点击和新输入。共享客户端是真实 API 测试；不等于原生 Obsidian 应用端到端。
