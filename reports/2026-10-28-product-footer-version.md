# 2026-10-28：统一页脚产品版本

## 现象与需求

后台旧页脚左右分散显示英文标语和产品署名，没有产品版本；公开博客页脚使用另一条静态标语，手机宽度下会隐藏。用户要求删除 `Made with intention`，居中显示 `Powered by MadeMe · v0.5`，版本读取配置而非写死在页面。

## 根因与修复

- 新增统一配置模块的 C 级发布常量 `PRODUCT_VERSION`，唯一产品显示版本为 `0.5`，不加入作者可编辑设置或 D1 存储。
- 新增静态共享组件 `ProductCredit`，公开首页、文章页、`Studio.astro` 和 `StudioShell` 共用；Astro 使用服务端渲染，不添加水合脚本。
- 后台删除旧英文标语，署名居中；保留账号底栏共享 56px 高度和交互逻辑。
- 公开页保留版权、站点名称和 RSS；等宽两侧网格确保中间署名居中。手机宽度下署名单独居中一行，不再隐藏版本。
- 不修改站点 tagline 及其其他用途，不改变 npm 包或健康接口版本。产品显示版本与包版本分别管理。
- 没有增加新的不可信数据边界：版本是类型明确的发布常量；现有 Zod 作者设置协议仍拒绝额外 version 字段。

## 验证

- `npm run check`：220 文件，0 错误、0 警告，5 条既有提示。
- `npm test`：73 文件、563 测试全部通过。

- `npm run test:smoke`：隔离本地 Worker HTTP 冒烟通过，新增真实首页 SSR 署名与配置版本断言；健康接口版本保持原值。
- `git diff --check`：通过。
- 浏览器布局/截图：本次未运行。此前本地 Chromium 在启动时受 socket 权限限制，本次没有修改安全参数或反复尝试；上述结构断言和 HTTP 测试不是视觉验收。

## 避免重复问题

发布时只调整 `src/modules/config/product.ts`，不要在布局、组件或设置界面复制版本字面值。新增页脚入口应复用共享组件；修改公共页脚样式时同时检查窄屏版本是否仍可见，以及版权、RSS 与中央署名是否保持各自位置。

本次仅准备源代码与测试，不部署或合并 main。
