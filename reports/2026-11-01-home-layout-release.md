# 首页布局正式提交

## 问题与行为

首页介绍横幅占用较多空间，精选区又因文章封面比例各异、文字自然高度不同而可见底部不齐。本分支删除介绍横幅及专用 CSS，保留站点导航、筛选、搜索和正文；刊物首页采用用户最终认可的图片底边/日期/标题首行基线对齐方案。

主图 3:2，桌面右侧两图平分扣除中间日期/标题后的高度，允许显示比例浮动，保留作者焦点与缩放、等比裁切而不拉伸。左摘要紧跟自己的标题，不参与强行等高；标题完整显示，无 72 字符规则。960px 以下正常纵向布局；宽屏若右上实际文案使每张图扁于 3:1，也按真实排版高度降级，避免图片挤没。

刊物首页使用 `HomeCover`，文章页、编辑器、工作台和其他主题继续使用文章设置的 `CoverFrame`；不改协议、发布排序、媒体处理、生产内容或凭据。正式规范见 [COVERS](../docs/COVERS.md)。

## 正式整理

- 过滤后的文章数不满三篇时清除旧降级状态；宽度观察和字体就绪测量在 effect 清理后失效，防止搜索改变版面后字体迟到触发旧回调。已在缺失失效保护时复现未处理异常，再用回归验证修复。
- 封面 E2E 由“首页与文章页比例永远相同”改为分别验证：首页按实际位置框检查比例、焦点、缩放与真实色带像素；文章页/编辑器/缩略图继续验证作者设置、补边和裁切。保存/取消/重新发布流程保留。
- 预览使用的 Canvas 封面、演示标题和提示只存在于隔离测试及执行器临时目录，不在产品源码、public 静态资源、数据库种子或部署入口中。
- 报告索引条目移至末尾，避免与并行媒体 PR 在顶部插入的索引记录发生无意义冲突；没有引入该 PR 的媒体删除代码。

## 发布边界与限制

基线为 main `ab2c131e734a688cb2a7d0f8f031ce7d570551a7`，本任务未直接部署、迁移数据库或改生产内容。测试使用真实本地 Worker/D1/R2 和 Chromium；未验证 Safari/Firefox、实体手机、生产素材构图和首屏布局稳定性。CSS subgrid 与内容测量的跨浏览器表现仍需后续专项验收。

仓库可见工作流只有测试和 AI 审核，没有部署工作流；不能据此排除外部托管平台监听 main 自动部署。合并动作须遵守 main 的严格 CI 规则，不绕过保护或失败检查。

## 合并前审核补充

首轮自动审核未发现严重问题，提出隐藏 h1 与 subgrid 回退等建议；经源码和实际测试独立核查后补齐：保留仅供辅助技术读取的站点名 h1，不恢复可见介绍区；桌面轨道映射仅在 `@supports (grid-template-rows: subgrid)` 生效，不支持时 CSS 与 JS 都降级为正常纵向列表。

测量逻辑补充空节点、非法 CSS 数值的安全降级和 clone 的 finally 清理，初始化宽度避免 Observer 首次重复测量，删除没有使用的 inline-size containment；`HomeCover` 注释澄清共享定位函数中的比例枚举不参与首页画框布局。

新增/扩展断言已在旧实现失败后验证修复：隐藏 h1 的唯一性及 1px 视觉边界、模拟不支持 subgrid 的 JS 回退、禁用 JS 并让浏览器选择 CSS `@supports not` 分支、缺失样式变量时保守降级、字体迟到后不执行失效测量。CSS 条件替换用于验证回退分支，不等于旧 Safari 实机验收。修改后再次通过 926 单测、20 集成测试、类型检查、构建、首页 2 项与封面 5 项浏览器回归；可见版面不变。
