# Markdown 附件导入修复

## 范围与基线

从实时远端 main `62e76a901e95543f3e32a7eae4d0347b3f7e6a19` 建立 `feat/markdown-attachment-import`，初始工作区干净。首次实施仅本地代码、测试与文档；首页和生产配置未改，没有使用生产凭据、真实笔记、生产文章或媒体。后续私有 Site 验收及用户授权提 PR 的记录见 [2026-11-02 交付复核](2026-11-02-markdown-attachments-pr.md)。

## 原因和修复

此前云端实际浏览器复现：单选 Markdown 后相对图片 URL 仍是本地路径，图片破损，保存前被校验阻止；wiki 嵌入保存为字面文字。共享客户端直接提交相对图片时，服务器会剥掉地址并保存文本，未调用媒体接口。用户附件的路径形状已用自制图片复现，没有读取真实附件。

现在网页选 `.md` 后显示站内窗口，显式补选附件文件或共同上级目录。共用模块识别标准、引用式与 wiki 嵌入，先校验所有引用，去重顺序上传，替换本站 URL，根据返回 MIME 创建 image/video/audio/file 块；全部成功且编辑序号匹配才替换正文，之后仍需手动保存草稿。失败、取消、重复点击和期间新输入有保护。

插件复用同一模块和现有 Zod 协议：确认后仅查 vault 路径元数据，逐个读取实际引用附件，不读其它笔记正文。旧服务器入口对未解析本地媒体明确返回 422，停止静默丢引用。没有修改媒体 URL 白名单、存储权限、数据库结构或发布规则。

路径规范化、URL 编码/NFC、百分号、越界/危险协议、同名歧义均有回归，代码示例不触发上传。HTML 媒体标签、SVG/MKV/笔记嵌入明确拒绝。只处理 `![]()`/`![[ ]]` 嵌入，普通文本链接和 frontmatter/天气不在本轮。

### 混合文件实证

| 自制文件 | 原字节 | 上传结果 | 真实验证 |
|---|---:|---|---|
| 中文 空格.png，452×875 | 4496 | WebP 1930 B | 中文/空格/编码，同图两处只传一次；保存刷新显示 |
| 动画.gif，96×64 | 355 | GIF 355 B，原字节一致 | 浏览器解码两帧不同，实际 img 截图序列画面变化 |
| 片段.mp4，160×96，2秒 | 18116 | video/mp4 18116 B | video 块，刷新后 play() 成功、currentTime >0.2s |
| 片段.mov，同一 H.264 流 | 18063 | video/quicktime 18063 B | 同上；未保证所有 MOV 编码 |

网页整个目录仅 4 次媒体 POST，未引用 TXT 没上传，草稿 PATCH 200。刷新后的 3 个 image 块（含同图两处）与 2 个 video 块都是本站 URL。共享客户端相同输入实际 4 次媒体 POST 201 + 1 次私有草稿 POST 201，visibility=draft、publishedAt=null；旧客户端相对图片明确 422/UNRESOLVED_ATTACHMENT。

其它浏览器用例：缺附件禁确认、SVG 拒绝、第二附件网络失败不保存不替换原正文，重试仅补传失败文件；取消不替换；重复确认仅一次请求；上传期间新标题输入使旧导入被拒，原正文/新标题保留。

## 边界

云服务器没有检测到原生 Obsidian，没有安装；真实共享客户端 API、SDK 检查和打包不等于原生桌面/手机宿主端到端。只实测当前 Chromium 的 H.264 MP4/MOV，未测 HEVC/ProRes、其它浏览器或全部音频。复杂嵌套 Markdown 排版、无扩展名旧视频 URL 类型推断未新增保证。

取消不能撤回已经到达服务器的上传，部分媒体会留库，不自动删除；同次预览复用已完成上传。文章创建没有幂等键，超时先查看 Studio，不自动重试创建。插件大图仍受现有服务端解码限制，超限明确失败。

模块和支持矩阵见 [README](../src/modules/markdown-import/README.md)。业务分支未部署到正式博客、未执行历史附件迁移；独立私有 Site 增量预览的后续结果见交付复核，不能等同正式博客上线。
