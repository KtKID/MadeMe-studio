# PR11 附件导入审核修复

针对提交 `285c95e` 的[审核意见](https://github.com/KtKID/MadeMe-studio/pull/11#issuecomment-6569330166)，复现后修复确定性问题；不把审核作业成功当作代码没有问题。正式博客与私有 Site 均未在本轮部署。

## 修复

- 集成媒体上传独立使用10分钟预算；普通 JSON 写入仍为20秒。`request-cancellation.ts` 以基本 AbortController 组合外部取消/超时，结束清理计时器和监听器，不依赖 `AbortSignal.any/timeout/throwIfAborted`。网页上传链没有被添加固定10分钟时限。
- 链接包裹标准、引用式和 wiki 图片在上传前明确拒绝，保留原文。暂不承诺可点击图片导入，避免插入空行后破坏外层链接、尤其是插件确认后直接保存损坏结果。
- Markdown 文件读取使用来源序号；新选择使旧操作立即失效，导入窗口按来源重新挂载，关闭和应用都核对来源。窗口自身也取消旧上传、忽略旧来源的进度/错误/应用/关闭；旧上传取消不把失败提示带到新窗口。等待期间真实正文/标题输入仍由原编辑时钟保护。
- wiki 路径按字面文件名处理百分号；标准 Markdown URL 才解码一次。`100%.png` 和 `100%25.png` 不再混淆；中文/NFC、合法同库父级引用仍支持，越界/危险协议规则不放宽。另修复 `./../` 合法笔记相对路径被另一种根路径解释误拒绝的问题。
- 文档分析/附件预检按输入缓存，进度更新不重新解析；代码/链接区间合并后使用单向游标，引用达到上限立即拒绝；上传结果用 Map 查找。
- 明确 API 兼容边界：HTML媒体标签和链接包图明确422，其余HTML是不可执行文字，缺链接定义仍保留文字；没有新增 Post/Media 字段或修改 Zod 协议。Audio/PDF 转块补协议验证，不把原审核的条件推测当作已发现的schema错误。

## 测试顺序与结果

先新增回归，在旧实现上观察7项失败：媒体20秒终止、缺少新AbortSignal API、链接图片损坏、百分号路径、A/B读取/窗口竞态及进度重复解析。随后新增 `./../` 回归在旧逻辑上单独失败；修复后通过。边界/清理/协议测试继续补充，不声称所有测试都先于全部实现。

- Vitest：113文件、990项通过；共享 Node 客户端/CLI：23项通过。
- 类型检查：0 errors、0 warnings、6 hints；build、Obsidian SDK 检查/打包、Chrome 打包通过。
- 临时 Worker/D1/R2 HTTP 回归与HTTP冒烟通过。
- 6项真实浏览器/API验收通过：新增A上传中切B、请求确实取消、B窗口和正文保留、保存B成功；新增链接包图无上传、两个百分号文件分别上传/保存/刷新且URL关联正确；原PNG/GIF/MP4/MOV混合文件夹导入、保存、动画/播放及其它取消/失败保护继续通过。
- 媒体等待用25MiB合成请求体和受控时钟模拟45秒传输，确认21秒时不中止、45秒成功；另验证10分钟上限、主动取消、预先取消和计时/监听清理。这是可重复的传输模拟，不是原生Obsidian或真实慢网测速。

新增浏览器用例起初还发现两处测试夹具问题：空格路径缺少标准Markdown尖括号，没有触发媒体请求；被应用取消的请求又在拦截器里重复abort。修正夹具后改为明确断言requestfailed取消事件，再检查新窗口和保存结果，未降低功能断言。

## 保留的边界

云端没有原生Obsidian，未声称桌面/手机宿主端到端通过。GIF与H.264 MP4/MOV在当前Chromium验证，HEVC/ProRes和全部浏览器/音频不保证。链接包图采用明确拒绝而非链接保真支持；已上传附件遇到取消/正文校验失败仍可留库，不自动删除，也未增加文章POST幂等键。超时需要核对实际结果。

推送后的CI和AI审核以最终head为准。若AI的120000字符输入上限截断，需另行检查被遗漏文件；本轮未修改工作流、权限、凭据或审核门槛。
