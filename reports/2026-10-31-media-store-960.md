# 2026-10-31：上传即缩到 960 WebP 落库，存量原图转换后删除

## 需求

KID：“改成上传时缩到960存储，现有原图也转换后删掉”。存储不再保留大原图，封面直接用 960 图。

## 实现

- `saveMedia`（上传、API/CLI/Markdown 导入、裁剪另存、AI 生成图的唯一入口）对静态 PNG/JPEG/WebP：按 EXIF 方向转正 → 等比缩到最大 960 宽（不放大）→ WebP q80（alpha 100）→ 只写 `media/<id>.webp`；D1 行 `mime=image/webp`、`size`、`name(.webp)` 同步更新。
- GIF、AVIF、动画 PNG/WebP、音视频、文档原样保存（SVG 本来不允许上传）。
- 转码核心 `src/server/media/raster-codec.ts`（纯函数，注入 Photon/jSquash），Worker 用 `image-wasm.ts`，迁移脚本用 `scripts/lib/node-codec.ts`，算法参数一致。键名约定在 `stored-image.ts`。
- 元数据：重新编码去除 EXIF/XMP/ICC。ICC 只识别不转换，按 sRGB 解释，广色域图可能轻微偏色（已写入模块 README）。
- 展示：srcset 仍为 480/960；落库图的 960 请求直接返回落库对象（`X-Image-Processing: s1-stored`，ETag=sha256），480 生成在 `image-derivatives/v1/<id>/s1/`；旧原图继续走旧路径，迁移前后 URL 不变。`/api/files/:id`（下载）返回落库 WebP。
- 前端：`imageSources` 附带 `data-fallback-src`，`Base.astro` 全局捕获 `error` 回退到 `/api/files/:id`，只回退一次并打印日志。
- 失败：超出 Worker 解码上限 413 `IMAGE_TOO_LARGE`；尺寸头无效 422 `IMAGE_DIMENSIONS`；解码/编码失败 422 `IMAGE_CONVERT_FAILED`；均经统一日志记录，不会退回保存大原图。

## 关键取舍

- **Worker 内存**：实测 12MP JPEG 解码+缩放 RSS≈285MB、24MP≈363MB，超过 Workers 128MB。服务端上限保持 400 万像素/单边 8192/16MiB。界面上传与裁剪另存先在浏览器（`upload-shrink.ts`，createImageBitmap 按方向转正）把超限图缩到 960 宽再上传，API/CLI 超限得到明确 413。
- **宽度不进设置页**：960 是 URL 契约（`960.webp`）、srcset 描述与迁移的基础，改动需升级 `IMAGE_STORE_RECIPE` 并迁移，故留在 `src/modules/config/limits.ts`。
- **是否已转换看 D1 行**（`mime=image/webp` 且 `object_key=media/<id>.webp`），wrangler CLI 写不了 R2 自定义元数据。
- 大屏高 DPR 下封面最多 960 宽，清晰度上限下降，这是 KID 选择的存储换取。
- 迁移后内部边缘缓存最多 600 秒可能返回旧衍生字节，无授权影响。

## 存量迁移

`scripts/migrate-media-960.ts`：`--dry-run`（只读）/`--apply`。apply 先 `wrangler d1 export` 整库，再逐张备份原图（核对大小+sha256）→ 本机转换 → 上传新键并回读校验 → 条件 UPDATE → 删除原图与旧衍生（R2 REST 列举 `image-derivatives/v1/<id>/`，含未入 manifest 的残留批次）。D1 失败撤回新键。

生产 dry-run（只读，2026-10-31）：10 张可转换，4826.6KB → 357.8KB；1 个 .mov 跳过；3 张带 ICC（两张浏览器导出的裁剪 JPEG、一张 PNG）；6 个旧衍生对象待删。
