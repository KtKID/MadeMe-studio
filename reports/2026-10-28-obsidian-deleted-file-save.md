# 删除本地导出文件后重新保存（2026-10-28）

## 根因与范围

用户先保存文章，手动删除本地 Markdown，再保存时收到“本地文章已修改”。不是浏览器缓存旧正文，而是授权根目录中的 `.mademe-export.json` 仍保留文章 ID、路径和上次写入的内容指纹：磁盘读取返回 NotFound 后转换为 null，旧逻辑把 null 与历史指纹不相等也当作本地内容修改。

附件存在相关缺陷：删除图片后规划可能重新使用相同空路径，但是否写入仅比较历史清单路径和指纹，因此误跳过补写。

本次仅修存储判断，不清缓存、不删除清单/用户数据、不改 UI 或目录授权：

- 真实 NotFound 的文章允许按原跟踪路径重建，包括文章标题变化的情况；清单仍用于识别同篇身份。
- 只有实际读取到且指纹匹配的图片才跳过写入；缺失图片重新落盘。
- 权限失败、IO 读取失败继续抛错，不伪装成文件不存在。
- 实际存在的本地改稿仍要求另存或明确覆盖；重建前出现陌生文章/图片仍拒绝覆盖。
- File System Access 不提供原子 CAS，多文件写入非原子事务的原有限制不变。
