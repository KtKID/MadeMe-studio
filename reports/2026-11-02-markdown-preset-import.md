# Markdown 导入复用笔记预设

## 现象与根因

既有“同步 Obsidian”设置已将 `{preset,handle}` 存入同源 IndexedDB；旧导入入口只拿普通 file input 的 File，没有复用这些句柄，无法确定 MD 相对仓库的位置，也无法按引用读取附件。8692493 修复了手动选择累加及清单，但没有补上正常预设自动导入链，不能当这次用户目标已完成。

## 本轮修改

- 仍在 `fix/markdown-import-guided-flow`，基于本地8692493；不新增数据库、预设字段或持久默认ID。多预设明确选择，不猜导出的list[0]。
- `PresetImportButton.tsx` 复用现有 `listPresets`；选择一篇 MD 的原生句柄。`preset-import.ts` 用所选根 `resolve` 确认路径，允许根内 `../`，拒绝越根或不同仓库的同名文档。
- 两图、GIF、本地视频自动查找/读取；远程链接保留。裸 wiki 名称仅必要时遍历有界目录元数据，拒绝歧义，不读其它文章正文、不上传全库、不调用本地写入。
- 清单显示预设、文章路径、逐项名称/类型/仓库相对路径/状态。预设模式取消手工补附件/选共同上级的主路径；缺失时明确停止。没有预设/不支持原生句柄的浏览器给现有设置入口及明确受限的单文件降级。
- 已有权限仅 query read；失效需用户点“重新授权此预设（只读）”，不请求 readwrite。上传前复核权限、根内位置、大小/修改时间；编辑器导入票据在读文件前取快照，取消/切换/新增输入不应用旧结果。
- `obsidian-local/contracts.ts` 仅最小扩展 read、FileHandle resolve 和可选 entries，既有导出写入实现及 IDB 结构不变。无新增 npm 依赖。

## 必须区分的未测边界

浏览器第9项用真实 native OPFS DirectoryHandle/FileHandle，经过既有设置UI和真实IDB，但系统picker返回受控。这证明了预设复用、原生句柄序列化/resolve、只读取引用、真实上传保存链；**不能证明外部OS文件系统选择器、实际用户目录授权/过期恢复弹窗已经通过**。权限失效/拒绝、多预设、重名、越根等由隔离函数/真实React状态测试覆盖。云端没有原生Obsidian宿主，本轮未安装或假装运行。

正式博客和测试Site不同origin，预设不能跨站继承；用户在Site测试需在该Site现有设置关联一次测试仓库。此限制不靠放宽权限绕过。
