# 2026-10-28：本地配置阶段不提前申请文件写权限

## 现象与定位

截图为 Chrome “允许此网站修改文件？”原生 File System Access 写权限确认，不是离站 beforeunload，也不是博客业务确认框。

本地源码中，`Settings.save()` / `putPreset()` 只校验并写 IndexedDB，没有调用 `requestPermission`、也不写 vault。能确证的过早请求点是共享 `pickDirectory()`：所有目录选择都使用 `showDirectoryPicker({mode:'readwrite'})`，配置或重选目录时就会申请写权限。不能把截图发生时机伪称为已复现了“putPreset 内请求权限”。此外文章保存入口原来每次无条件调用 requestPermission。

## 修复

- 目录选择改为 `mode:'read'`；配置预设只保留句柄与参数，不要求修改目录中的文件。
- 实际“保存本次快照”点击后才查询写权限：granted 直接继续；prompt 申请一次；denied 明确停止并提示手动管理权限或另选位置，不自动重复弹窗。
- 没有删除、遮挡或绕过浏览器必要授权。目录选择仍会打开系统选择器/读取授权；首次真正保存文章、权限过期或被撤回后，浏览器仍可能需要原生写入确认。

## 验证

先修改目录选择模式断言并新增 granted/denied/prompt 回归，观察4项失败；实现后两文件29项通过。已有“修改预设后保存”回归补充确认没有调用权限请求或写文件适配器。

全仓78文件624项通过；check无错误/警告、5条提示；build、HTTP冒烟通过。真实Chrome权限弹窗没有在当前受限环境复现，不将模拟状态测试称为原生授权验收。未推送或部署。
