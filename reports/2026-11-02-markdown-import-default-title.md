# Markdown 导入补齐默认标题

## 原因与修复

普通文件及仓库导入共用Editor的applyMarkdownImport。原实现仅在title为空字符串且正文含H1时赋值，没有所选MD文件名的fallback，也未把纯空白标题视为空。

确认导入成功、编辑时钟校验通过后：保留已有有效标题；空/纯空白标题优先沿用正文首个H1，否则用原Markdown File.name去掉末尾.md/.markdown（大小写兼容）作为默认值。多点和中文文件名保留。只改标题赋值，不改正文或解析frontmatter；预览、取消和失败不会提前填标题。

## 验证

- 新回归在旧实现先观察两项失败：无H1中文文件名、空白标题/多点大写扩展名。修复后真实React Editor按钮链20项通过，包含保存PATCH标题、H1优先、有效手动输入保留及取消不改标题/正文。
- 普通磁盘文件通过正常网页file chooser导入，覆盖无H1、多点/中文/大小写扩展名、有H1、手动标题、空白标题和取消，实际保存草稿并重新打开验证；原始正文/H1仍在。
- 仓库原生句柄导入无H1的“仓库.中文标题.MARKDOWN”，默认标题“仓库.中文标题”，真实API保存并刷新验证正文与标题。受控native OPFS picker不当作外部OS授权验收。
- 全部120文件1065项单测通过；浏览器12项（9普通/媒体，含4组普通标题场景；3原生仓库/迁移，含仓库标题场景）通过。其余仓库迁移、级联和媒体导入回归保留。check 0错误/0警告/6既有hints，build通过。
