# MadeMe Studio 日常架构巡检规范

## 目标与执行时间

每天从架构设计、模块边界、职责归属、契约事实源、实现漂移和循环依赖六个方面审查 MadeMe Studio，保留可复核的源码路径、反例与结论变化。

时区为 `Asia/Shanghai`，首轮为 **2026-11-01 03:00**，之后每天 03:00。2026-10-31 跳过；补跑时先核对实际日期及当天已有报告，复用当天已完成结果。

## 使用现有技能

| 工作 | 入口 | 输出 |
|---|---|---|
| 架构正确性、模块归属、职责、重复事实源、依赖方向 | `x-audit-arch` | `reports/audit/audit-arch-YYYYMMDD-HHmmss.md` |
| 结构问题触达真实状态、权限、数据或公开行为 | `x-cr` | `reports/cr/cr-report-YYYYMMDD-HHmmss.md`，使用 x-cr-v2 并校验 |
| 项目背景、每日取证顺序及前后轮对账 | 本规范 | 当日主架构报告及其证据目录 |

复用上述技能，本规范提供 MadeMe 的项目约定与每日衔接。架构采用 P1/P2/P3；正确性采用 P0/P1/P2，分别计数，关联问题互相回指。技能从当前会话可用目录加载，记录实际读取版本；使用 skill 的子代理要求时，由主代理统一证据与最终结论。

## 1. 固定本轮事实基线

1. 记录上海时间、仓库路径、当前分支、HEAD、工作区状态和目标来源。保留现有未提交改动。
2. 读取 `AGENTS.md`、`docs/DEVELOPMENT.md`、`docs/SECURITY.md`、相关 spec/tech-design 和各模块 README。
3. 检查远端默认分支是否前进。默认巡检最新远端 `main`；本地与远端一致时直接复用当前源码。远端已前进时，将指定提交读入临时副本开展审查，当前工作区继续保持原样。远端读取受阻时明确本地基线及证据缺口。
4. 当前工作区的业务改动作为独立范围记录，明确它们与远端提交的关系；隔离两套路径、行号、依赖图和测试结果。
5. 读取最近一次完成的架构/CR 报告；首轮承接 `audit-arch-20261031-004542.md` 和对应 CR。历史报告的结论绑定其 `67f02f0` 基线。
6. 初始报告提交 PR 时，远端 `09dbd84` 已领先该基线 6 个提交，涉及文章类型、发布状态与 CI；下一轮据实际最新 SHA 复核这些变化。

报告中的“当前”始终指本轮明确审查的提交或工作区快照。把测试结果与执行源码、依赖版本、环境和命令绑定。

## 2. 先判断总体设计，再检查模块

从产品规模与运行方式评估 Astro SSR、React 交互、D1 结构化状态、R2 媒体和模块化单体的适配性。每个建议说明当前约束、具体后果以及保留或调整该设计的依据。

维护覆盖矩阵，至少检查：

| 区域 | 主要检查 |
|---|---|
| middleware / pages / server/api / page-data | 平台注入、SSR 与 HTTP 编排、鉴权位置、入口规则一致性 |
| auth | Identity 契约、认证分发、Google/密码适配、CSRF、scope、会话状态 owner |
| content / repository / db | 草稿与发布快照、CAS/修订、SQL 与业务职责、模型/迁移/snapshot 同步 |
| media / AI | 已发布引用权限、配置生效、对象与元数据提交、提供商协议/传输/持久化边界 |
| shared / config / embed / content-check | 跨端协议、纯规则、默认值与枚举、依赖闭包和事实源归属 |
| StudioShell / navigation / performance | 路由与历史 owner、业务面板状态、身份生命周期、采集与业务依赖方向 |
| Editor / Settings / shared UI | 文档状态 owner、多工作流锁与生命周期、网络边界、UI primitive 和策略职责 |
| local-export / obsidian-local | 纯准备、浏览器目录适配、授权根、落盘/取消/部分失败边界 |
| 后续新增领域模块 | 明确公开入口、状态 owner、上游/下游和现有架构约定 |
| integrations / build / migration | 共享协议依赖闭包、最终交付白名单、生成物、版本和可继续迁移能力 |

每天重建全量依赖视图，结合最近改动、调用邻居和既有高风险边界深入取证。覆盖矩阵写清本轮直接验证与沿用历史证据的区域。

## 3. 构建并解释依赖图

初始可复用 `scripts/audit-imports.mjs`。传入本轮源码根、可用 TypeScript 包路径与输出路径；在隔离目录运行，原项目源码保持原样。

```sh
node /path/to/audit-imports.mjs /path/to/review-source /path/to/typescript /tmp/import-graph.json
```

检查 AST import/export、字面量动态 import/require、import type 和 Astro frontmatter/script。计算运行时强连通分量，再计算含类型边的分量；列出完整闭环和边的文件/行号。登记解析缺口、动态边与构建器虚拟模块边界。

对照上次图检查新增跨层边、运行时环、类型归属回流和跨模块内部 import。领域模块双向耦合、文件级运行时环和 import type 分别说明。feature 内 UI/core 共置结合模块 README 判断；文件行数用于定位热点，问题结论还需职责、状态和变化方向证据。

## 4. 检查规则与状态的单一归属

对于同一业务字段、枚举、默认值、路由集合、URL 策略、权限判断与错误协议，列出各处定义和真实消费者。确认 SSR/API、保存/发布/阅读、源模型/迁移/生成器、完整仓库/交付 stage 是否遵守同一语义。

重点回查初始问题：认证 runtime SCC、导航归属、settings/AI 耦合、跨端 DTO、shared/ui 混合职责、Editor 工作流状态闭包，以及 B1–B5 的迁移、打包、媒体条数、mailto 和失败日志。

每条架构发现必须包含：具体位置、当前 owner、目标 owner、完整依赖或调用路径、演进时的腐化机制和最小治理边界。抽象或分层建议同时说明现有调用者如何迁移及需要保留的状态/事务语义。

## 5. 用 x-cr 验证行为后果

结构发现触达用户可见行为、权限、状态或持久化时，按 x-cr 读取归属不变量，构造最小反例，再检查上游 guard、schema、调用者保护、事务及错误兜底。

优先复用现有测试，在隔离副本或内存数据库中取证。涉及平台差异时采用对应运行时；记录替身边界、依赖 lock 和环境。真实外部账号、计费模型、正式数据与原生浏览器授权按独立验收范围处理。

已有测试通过仅支撑其实际断言覆盖。反例失败、候选被上游约束排除、环境受阻和待确认契约分别记录。x-cr 报告使用其校验器验证 schema 后归档。

## 6. 对照上次结论并保持编号

当日架构主报告是本轮问题状态的事实源，引用首次发现的报告和证据。沿用既有 A/B 编号；新问题从历史最大编号继续分配。A 对应结构，B 对应正确性，关联问题保留互相回指。

| 状态 | 要求 |
|---|---|
| 新增 | 本轮证据首次支持该问题 |
| 持续 | 当前提交中的路径或反例仍成立 |
| 恶化 | 影响范围、依赖环或错误结果扩大，列前后差异 |
| 已解决并验证 | 原依赖路径已消除或原反例已通过，列执行证据 |
| 待复核 | 源码/环境/契约变化使既有证据需补充 |

原问题的证据被新测试或契约削弱时，说明修正原因。持续问题以状态表承接，详情引用首次报告和最新复核证据。

## 7. 归档与交付

每天保存架构报告和 `reports/audit/evidence-YYYYMMDD-HHmmss/`。主报告依次呈现：架构判断、较上次变化、模块矩阵、依赖图结论、问题状态、最重要的后续动作和覆盖限制。各条发现具有严重度、置信度、源码基线、文件/行号与验证方式。

保持历史证据的原始语义。跨日期、跨提交引用使用仓库相对链接或固定提交链接，方便 PR 和本地阅读。公开交付使用脱敏报告和验证汇总；本机路径、逐文件指纹、原始内部日志和完整机器依赖图保留在本地。

定时任务授权范围为读取、依赖分析、隔离验证及本地报告写入。应用源码修改、自动修复、部署、合并和后续提交/推送/PR 由后续明确任务承接。首次报告 PR 单独交付。

执行结束给出当日报告路径、两类严重度计数、最重要的变化和下一步。运行受阻时列明实际原因、已完成覆盖与最短补证动作。
