# 文章：Markdown 网页导入和内部文章信息

> spec：articles
> 主要入口：工作台 → 文章编辑页 → 导入
> 状态：在用
> 最近更新：2026-11-28

## 本次目标与完成条件

- 范围：网页导入，包含从已连接的 Obsidian 仓库选稿和手动选 Markdown。
- 1 期：自动设封面、显示内部文章信息、导入前检查 CID、应用导入标题。
- 验收：从网页导入一份带 CID、封面路径和重复首图的稿件。保存并重新打开后，管理员在现有信息行里看到 CID。发布后的阅读页各展示一次文章标题和封面，公开页面、公开 API 和 RSS 都只提供公开字段。再次尝试把同一个 CID 导入另一篇文章，提示出现在附件处理之前，现稿保持原样。

## feat01: 自动设置文章封面

> 状态：已验收
> 期次：1 期

场景1: 用文件头指定封面

依据与价值：用户要求从 `cover` 自动设置文章封面，节省手动选择操作。

- GIVEN Markdown 文件头有 `cover: images/cover.jpg`，该路径相对于 Markdown 文件，图片可以通过现有授权或选中的附件读取
- WHEN 管理员确认导入
- THEN 这张图自动填入文章封面，正文未引用该图时也适用。保存后重新打开文章仍可看到封面。

场景2: 封面与正文首图相同

依据与价值：用户确认设为封面后删除导入正文里的重复图片，读者只看见一张封面。

- GIVEN `cover` 和正文首图指向同一份文件
- WHEN 封面成功导入
- THEN 该文件只上传一次。导入后的正文移除重复首图，封面栏保留该图，其他正文图片照常导入。

场景3: 封面附件缺失或上传失败

依据与价值：沿用现有附件导入的失败处理，作者能看到失败原因并保留当前编辑内容。

- GIVEN `cover` 指定的附件缺失、无法访问或上传失败
- WHEN 管理员尝试导入
- THEN 导入界面提示失败路径或原因，当前草稿的封面、正文和内部信息保持原样。

## feat02: 在编辑页显示内部文章信息

> 状态：已验收
> 期次：1 期

场景1: 保存并在已有信息行展示内部属性

依据与价值：用户选择保存 CID 和明确指定的字段，并指定截图中的现有信息行。

- GIVEN Markdown 文件头有 `cid`，首版明确的内部字段为 `cid`
- WHEN 管理员导入并保存文章，再从工作台打开
- THEN 文件头属性区从文章正文里剔除。`cid` 随文章保存，在类型、日期和「自己的文字，自己的空间」同一行直接显示。`cover` 用于封面字段，标题按 feat04 处理。只有明确指定的内部属性随文章保存。

场景2: 公开读取只返回公开内容

依据与价值：用户要求内部文章信息供管理员查询，读者只读取对外内容。

- GIVEN 一篇保存了内部属性的文章已发布
- WHEN 访客打开阅读页或通过公开 API、RSS 读取
- THEN 读取结果只含公开文章字段。页面源码和公开响应均无内部属性，正文使用导入完成后的内容。

## feat03: 导入前检查 CID 占用

> 状态：已验收
> 期次：1 期

场景1: CID 已被其他文章占用

依据与价值：用户要求博客在本地检查之外独立拦截重复 CID。按内容索引规则，已分配的 CID 随同一篇文章保留。

- GIVEN 所选 Markdown 的 `cid` 已关联到另一篇博客文章，包括草稿、已发布文章和可恢复的回收站文章
- WHEN 管理员选中 Markdown，站点刚读出 `cid`
- THEN 提示该 CID 已被占用，禁止这次导入。检查发生在附件读取、上传和更改当前文章之前。两次导入同时通过预检时，最终也只能有一篇文章保存该 CID。

场景2: 重导同一篇文章

依据与价值：CID 标识内容本身，同一篇文章可用原稿更新内容。已有 CID 用于保持关联。

- GIVEN 正在编辑一篇已有 CID 的文章，所选 Markdown 带相同 CID、缺少 CID 或带不同 CID
- WHEN 管理员发起网页导入
- THEN 相同 CID 或缺少 CID 时沿用现有关联并继续导入。不同 CID 时在附件处理前提示关联不一致并停止，保留当前稿件。

## feat04: 导入标题只显示一次

> 状态：已验收
> 期次：1 期

场景1: 文件头标题进入网站标题栏

依据与价值：用户要求导入的标题自动成为网站文章标题，读者只看见一次正文标题。

- GIVEN Markdown 文件头有有效的 `title`，或者正文开头是可直接提取文字的一级标题
- WHEN 管理员确认网页导入
- THEN 文件头 `title` 优先，缺省时采用开头一级标题。采用的标题填入网站标题栏。正文开头一级标题与采用的标题相同时，从导入正文移除。保存后重新打开，标题仍位于文章标题栏。

场景2: 保留正文里的其他标题和内容

依据与价值：标题去重只面向文件开头的文章标题，正文结构和附件各有用途。

- GIVEN 开头一级标题与文件头标题不同，或者正文含章节标题、代码示例或内嵌媒体
- WHEN 管理员导入
- THEN 这些正文内容照常显示。文档未指定标题时保留编辑器已有标题，空白标题仍可由文件名补上。
