# 封面规范与当前实现

本文是封面设计约定和实现状态的统一入口，关联[模块索引](MODULES.md)、[封面源码说明](../src/modules/cover/README.md)及[图片衍生说明](../src/modules/image-delivery/README.md)。以下布局是本分支实现，发布状态以合并及部署记录为准。

## 首页布局

| 位置             | 展示规则                     | 1140px 桌面容器示例                       | 作用         |
| ---------------- | ---------------------------- | ----------------------------------------- | ------------ |
| 左侧主文章       | 3:2                          | 约 715×477 CSS px                         | 重点展示     |
| 右侧上下两篇     | 分配图片剩余高度，比例可浮动 | 每张约 397×195 CSS px，取决于中间文案高度 | 次级展示     |
| 下方普通文章网格 | 16:9                         | 每张约 272×153 CSS px                     | 宽屏每行四篇 |

桌面保持 1.8:1 列宽，主图顶边与右上图顶边对齐，主图底边与右下图底边对齐。右上日期和标题保留在两图之间，扣除文案与间距后，两图均分剩余高度；不是强制右图 16:9，也不拉伸图像。下方两篇日期同排，标题按第一行基线对齐，以适应主次不同字号。左摘要紧跟自己的标题，不参与列高补齐。

以上是随容器变化的示例尺寸，不是固定宽度。960px 以下按正常纵向布局排列，次级图片恢复 16:9。更宽时，若实际排版的右上文案令每张右图扁于 3:1，也降级为纵向列表，防止图片被挤没。标题完整显示，不按字符数量切换布局，没有 72 字符规则。正文列表在平板/手机通常两列，360px 以下一列。

## 首页与文章设置的边界

- 刊物首页使用 `HomeCover`，按位置定义框；只复用作者 `focusX/focusY/zoom`，使用等比 cover 裁切，不写回文章数据。无图时抽象占位也遵循同一布局几何。
- 文章页、编辑器、工作台和其他首页主题仍使用 `CoverFrame`，沿用文章自己的比例与 contain/cover。文章设置与发布快照保持原协议，布局调整不批量改图或改文章。
- 文章 Zod 比例枚举仍是 `original`、`1:1`、`4:3`、`16:9`，没有新增 3:2 的作者编辑预设；首页主图 3:2 是展示层画框，与协议枚举分开。
- 渲染依据 [HomeFeaturedPosts](../src/components/content/HomeFeaturedPosts.tsx)、[首页 CSS](../src/components/content/home-featured-posts.css)和[封面契约](../src/modules/cover/contracts.ts)。桌面采用 CSS subgrid 和内容测量；不支持 subgrid 时有 CSS 与 JS 的纵向回退。当前有真实 Chromium 及回退分支模拟验证，其他浏览器与首屏稳定性仍需专项验收。

## 素材、裁切和显示

原始素材保留一份完整构图，主体及文字尽量避开边缘，便于同一张图用于 3:2 和 16:9。展示比例和文件比例是两件事：1536×1024 原图生成的 960×640、480×320 仍是 3:2；放入 16:9 框时才决定裁切或补边，不把所有衍生文件硬裁成 16:9。

- `contain` 完整显示，预设比例框使用白色补边；`original` 不裁切、不补框。现有组件显示宽高上限为 1024 CSS px，小容器内缩小；存储图最大 960 宽，高 DPR 大屏上封面不会比 960 更清晰。
- `cover` 按目标比例铺满，焦点 `focusX/focusY` 为剩余空间的 0–100% 位置，默认居中；`zoom` 为 1–3。选择 16:9 时应检查主体是否被裁掉，再调焦点。首页 3:2 框沿用同一焦点与缩放语义，不需要改动作者保存的比例。
- 比例、fit、焦点和缩放随文章草稿及发布快照保存；更换封面保留比例/fit，重置焦点和缩放。媒体库“裁剪另存”会生成新文件，与只调整展示参数不同，原图仍保留（落库图为 960 宽 WebP）。
- 圆角由 CSS 裁切展示，当前首页圆角 6px；无需为圆角上传透明 PNG，也不应把透明圆角烘焙进原图。

照片和复杂拼贴优先使用 WebP 展示；JPEG 可作为不需要透明的原始照片或兼容导出选择。需要透明背景的图使用 PNG 或支持 alpha 的 WebP，JPEG 不保留透明。细字/线稿须检查有损编码伪影，不能只用体积判定质量。应用静态 PNG/普通 JPEG/WebP 的展示衍生统一为 WebP；动画、EXIF 等降级边界以[图片模块](../src/modules/image-delivery/README.md)为准，不重复维护格式规则。

## 原图、展示图与缓存

上传时即把静态位图按方向转正、等比缩到最大 960 宽、q80 WebP 落库，不保留大原图；封面 960 档就是落库图本身，480 档首次有权限的请求时生成。动画、GIF 等原样保存。`srcset/sizes` 挑选展示图，下载与裁剪输入使用落库图（因此裁剪另存最大 960 宽）。外站图片不代理处理。历史原图由一次性迁移脚本转换后删除，迁移前继续走旧衍生管线，文章 JSON 无需改写。

公开衍生路径必须核对当前公开发布快照里的真实媒体引用，忽略访客身份；鉴权在边缘缓存、ETag 和 HEAD 判断之前。私有路径复用原图阅读权限，响应 `private, no-store`。公开图片浏览器缓存 60 秒，内部边缘字节缓存 600 秒；撤回后下一次网络请求拒绝，但浏览器已有新鲜副本最多仍可使用 60 秒，已经下载的文件无法召回。缓存键、失败处理和并发提交规则统一维护于[图片模块](../src/modules/image-delivery/README.md)。

## 实际素材示例与验证边界

同一张 1536×1024 PNG 原图为 2,962,682 字节。独立本地 Pillow/libwebp、q80、method 6 压缩得到：

| 文件 | 尺寸    | 字节数 | 相对原图减少 |
| ---- | ------- | ------ | ------------ |
| WebP | 960×640 | 97,630 | 96.70%       |
| WebP | 480×320 | 27,876 | 99.06%       |

这是**实际素材的独立压缩示例**，不是应用编码器输出。应用用 Photon 0.4.0 WASM 解码/Lanczos3 缩放，jSquash WebP 1.5.0 WASM q80、method 4 编码；算法、参数与编译版本可能不同，同为 q80 也不保证相同体积或画质。

应用仅用合成图在本地真实 Worker 验证了编码、透明度、缓存与权限；真实素材的应用编码体积/耗时、生产峰值内存及 CPU 预算尚未验收。当前输入防护为 16MiB、400 万像素、单边 8192，具体限额只在[配置源码](../src/modules/config/limits.ts)维护。可捕获的处理失败会记录日志并返回错误，原图不变；同步 WASM 没有应用级可抢占 CPU 时限，被平台强制终止时不能保证转换成应用 503。

本分支未生产部署，线上上传/缓存行为尚未改变。原始封面功能的阶段历史保留在 [cover-plan](cover-plan.md)，其中早期现状和方案不能当作当前实现；查当前约定应从本文开始。
