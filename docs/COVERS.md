# 封面规范与当前实现

本文是封面设计约定和实现状态的统一入口，关联[模块索引](MODULES.md)、[封面源码说明](../src/modules/cover/README.md)及[图片衍生说明](../src/modules/image-delivery/README.md)。尺寸与比例约定不表示代码已经全部实现；本轮补文档，不修改首页布局或文章设置协议。

## 已确认的首页设计约定

| 位置 | 目标展示比例 | 桌面基准示例 | 作用 |
| --- | --- | --- | --- |
| 左侧主文章 | 3:2 | 约 720×480 CSS px | 重点展示 |
| 右侧上下两篇次级文章 | 16:9 | 每张约 400×225 CSS px | 次级展示 |
| 下方普通文章网格 | 16:9 | 每张约 272×153 CSS px | 宽屏每行约四篇 |

这里只定义两种展示比例。主次由展示尺寸和排版区分，不为普通列表再增加第三种比例。上述宽高是桌面容器下的基准示例，**不是固定宽度或手机尺寸**；实际随容器等比变化，窄屏需要重排，不能强塞桌面宽度。

## 当前已实现与待实现的差异

- 已有首页前三篇左大右双卡、后续四列网格，平板两列，窄屏重排；有图时统一使用 `CoverFrame`，继承每篇文章自己的 `coverSettings`。真实封面没有按主/次/普通位置强制改成上述比例。
- 当前 Zod 比例枚举是 `original`、`1:1`、`4:3`、`16:9`，**没有 3:2 预设**。3:2 原图可以选 `original` 完整展示，但这不等于系统已经支持任意图的 3:2 裁切。
- 无封面时使用 CSS 抽象占位；占位规则包含桌面次级约 2.8:1、手机主图 16:10 和次级 4:3 等，并未完全采用新设计约定。有真实封面时 `.has-cover` 会取消这些占位比例，让文章设置决定高度。
- 待实现：明确首页位置比例与文章自定义比例的优先级、补齐所需 3:2 协议/调整器能力，以及按新约定验证手机布局。不能只改 CSS 就声称完成，也不能擅自覆盖已保存的作者裁切。

当前行为依据 [HomeFeaturedPosts](../src/components/content/HomeFeaturedPosts.tsx)、[首页 CSS](../src/components/content/home-featured-posts.css)、[封面契约](../src/modules/cover/contracts.ts)。上述差异本轮只记录，未实施布局调整。

## 素材、裁切和显示

原始素材保留一份完整构图，主体及文字尽量避开边缘，便于同一张图用于 3:2 和 16:9。展示比例和文件比例是两件事：1536×1024 原图生成的 960×640、480×320 仍是 3:2；放入 16:9 框时才决定裁切或补边，不把所有衍生文件硬裁成 16:9。

- `contain` 完整显示，预设比例框使用白色补边；`original` 不裁切、不补框。现有组件显示宽高上限为 1024 CSS px，小容器内缩小，这个上限不会修改存储原图。
- `cover` 按目标比例铺满，焦点 `focusX/focusY` 为剩余空间的 0–100% 位置，默认居中；`zoom` 为 1–3。选择 16:9 时应检查主体是否被裁掉，再调焦点。未来 3:2 框也应沿用相同焦点语义，目前仅作为设计要求。
- 比例、fit、焦点和缩放随文章草稿及发布快照保存；更换封面保留比例/fit，重置焦点和缩放。媒体库“裁剪另存”会生成新文件，与只调整展示参数不同，原图仍保留。
- 圆角由 CSS 裁切展示，当前首页圆角 6px；无需为圆角上传透明 PNG，也不应把透明圆角烘焙进原图。

照片和复杂拼贴优先使用 WebP 展示；JPEG 可作为不需要透明的原始照片或兼容导出选择。需要透明背景的图使用 PNG 或支持 alpha 的 WebP，JPEG 不保留透明。细字/线稿须检查有损编码伪影，不能只用体积判定质量。应用静态 PNG/普通 JPEG/WebP 的展示衍生统一为 WebP；动画、EXIF 等降级边界以[图片模块](../src/modules/image-delivery/README.md)为准，不重复维护格式规则。

## 原图、展示图与缓存

本分支上传仍保存原始字节。**首次有权限的展示请求**才按需生成 480/960 宽、q80 的等比 WebP，不放大；不是上传结束就已经压缩。`srcset/sizes` 用于挑选展示图，下载及裁剪输入保留原图。外站图片不代理处理，历史本地媒体无需重写文章 JSON，正常访问时进入同一管线。

公开衍生路径必须核对当前公开发布快照里的真实媒体引用，忽略访客身份；鉴权在边缘缓存、ETag 和 HEAD 判断之前。私有路径复用原图阅读权限，响应 `private, no-store`。公开图片浏览器缓存 60 秒，内部边缘字节缓存 600 秒；撤回后下一次网络请求拒绝，但浏览器已有新鲜副本最多仍可使用 60 秒，已经下载的文件无法召回。缓存键、失败处理和并发提交规则统一维护于[图片模块](../src/modules/image-delivery/README.md)。

## 实际素材示例与验证边界

同一张 1536×1024 PNG 原图为 2,962,682 字节。独立本地 Pillow/libwebp、q80、method 6 压缩得到：

| 文件 | 尺寸 | 字节数 | 相对原图减少 |
| --- | --- | --- | --- |
| WebP | 960×640 | 97,630 | 96.70% |
| WebP | 480×320 | 27,876 | 99.06% |

这是**实际素材的独立压缩示例**，不是应用编码器输出。应用用 Photon 0.4.0 WASM 解码/Lanczos3 缩放，jSquash WebP 1.5.0 WASM q80、method 4 编码；算法、参数与编译版本可能不同，同为 q80 也不保证相同体积或画质。

应用仅用合成图在本地真实 Worker 验证了编码、透明度、缓存与权限；真实素材的应用编码体积/耗时、生产峰值内存及 CPU 预算尚未验收。当前输入防护为 16MiB、400 万像素、单边 8192，具体限额只在[配置源码](../src/modules/config/limits.ts)维护。可捕获的处理失败会记录日志并返回错误，原图不变；同步 WASM 没有应用级可抢占 CPU 时限，被平台强制终止时不能保证转换成应用 503。

本分支未生产部署，线上上传/缓存行为尚未改变。原始封面功能的阶段历史保留在 [cover-plan](cover-plan.md)，其中早期现状和方案不能当作当前实现；查当前约定应从本文开始。
