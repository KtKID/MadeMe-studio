# 保存到 Obsidian：实际保存规则

本文描述网站“保存到 Obsidian”的浏览器本地保存，不是后台同步，也不改变 Obsidian → 网站的单向发布集成。以下为当前实现，不是计划中的优化。

## 模块职责与方向
- `local-export` 只准备当前文章快照、Markdown 与媒体清单，不反向依赖 Obsidian，也不写本地目录。
- `obsidian-local` 的浏览器适配器校验授权根、分配安全路径、下载附件、写 Markdown 和清单；设置/保存 UI 负责用户确认、权限与错误反馈。
- 这是**网站 → 本地目录的手动单向导出**，不是双向同步：不会监视 Obsidian 修改、自动上传、合并正文或定时同步。现有 Obsidian → 网站发布集成独立，不被此模块替代。
- 目录句柄留在当前浏览器 IndexedDB，不上传后端，不将访问令牌放进 Obsidian URI。

## 选择与授权
- 预设和目录句柄只保存在当前浏览器。新增预设不预填文章子目录，需选择目录后才能保存配置；旧预设不迁移。
- 仓库根必须能读取直属 `.obsidian` **目录**。选择根、编辑旧预设、确认配置和实际文章写入均检查实际目录，不以缓存标志替代。文章子目录不需要自己的 `.obsidian`。
- 保存预设只写浏览器配置，不请求文件写权限。保存文章时才查询/必要时请求浏览器写权限。
- 路径在已授权根内解析。例如文章目录 `01_笔记`、图片规则 `../asset`，图片目标是根下 `asset`。实际缺哪个目录会分别提示；创建必须点击“创建目录并保存”；底层文件写入不会隐式重建下载期间被外部删除的目录。
- 保存使用点击时的当前稿快照，不发布网站文章。成功关闭弹窗；打开 Obsidian 是附属操作，不等于已确认应用成功打开。

## `#` 字符：文件名兼容处理，不过滤文章内容
- 当前实现对**新分配的本地文件 basename** 将 `#` 替换为 `_`，文章和媒体均适用。例如文章标题 `学习C#` 首次导出为 `学习C_.md`；`C#` 没有特殊豁免。本轮未改这一算法。
- 正文中的 `C#`、Markdown 标题语法 `# 标题`、文章原始标题和网站媒体原名均保持原文，不做全文替换。此规则只针对文件路径组件。
- 旧清单若指向含 `#` 的文件，旧文件不改名、不删除；分配兼容的新文件并更新映射，不强行覆盖同名文件。
- 用户选择的根/文章子目录、规范化后的图片目录包含 `#` 时拒绝并提示“目录名含 #，Obsidian 无法正确打开，请选择其他目录。”，不擅自改目录名；仅 Markdown 模式也执行此路径校验。
- 对 URL 做 `%23` 编码，不等于 Obsidian 能把它当作文件名中的字面 `#`。[官方 URI 文档](https://obsidian.md/help/uri) 将 `Note%23Heading` 定义为跳转到标题；[官方论坛的内部链接说明](https://forum.obsidian.md/t/file-attachment-uri-doesnt-support-hash-symbol-except-file-but-it-doesnt-encode-as-23/98547) 也说明此限制。历史 1.14.5 分段测试中尝试的编码未能可靠打开，替换后的产物可打开；这不是证明所有可能方案都不成立，也不是本轮重新完成原生实测。

换根后须重新选择文章子目录，不能沿用之前在其它根下选择的相对路径；取消或无效根不丢旧选择。

## 身份与清单，不靠文件名判重
未保存站内的新稿使用临时 UUID；首次站内保存后改用服务端文章 ID。因此跨此身份转换再次本地导出可能产生第二个 MD，不自动迁移或合并，旧文件保留。以下复用规则只针对相同文章 ID。

根目录下 `.mademe-export.json` 保存：
- `articles[articleId] = { path, digest }`：文章 ID 对应相对路径及上次导出正文的 SHA-256。
- `media[mediaId] = { path, digest }`：媒体 ID 对应相对路径及媒体字节的 SHA-256。

哈希用于内容比较，不用来重新生成媒体身份。首次文章文件名为安全处理后的“标题.md”；媒体优先使用原文件名。同名但身份不同或磁盘上已有陌生文件时，追加稳定 ID/必要序号，不能仅凭文件名覆盖。

## 重复保存的判断顺序
1. 校验根、路径和所需目录，读取并验证清单。
2. 按文章 ID 查找记录。**相同文章 ID + 相同目标文章目录**复用已记录路径，而不是重新按当前标题找文件。
3. 读取该路径的实际正文并计算哈希：
   - 与清单相符：可继续保存网站快照。
   - 文件确实不存在（NotFound）：允许在原路径重建，不把删除误报成本地编辑。
   - 实际存在但哈希不同：提示本地修改，必须另存或明确确认覆盖。取消保留原稿；权限和 IO 错误不当作“文件不存在”。
4. 准备并下载本次需要的媒体，全部取齐后开始附件写入；提交正文前复核本次所有附件（含先前决定复用的图片）实际存在且哈希匹配，再比较正文磁盘内容与授权基线。发现期间删除/新修改/陌生文件则停止，不静默覆盖。
5. 写入正文，更新文章映射与正文哈希，最后写入清单。

**当前并未实现“同内容完全跳过”：即使导出的 Markdown 与上次相同，Markdown 和清单仍会重写。** 已实现的是路径身份复用、冲突保护以及满足条件时跳过图片磁盘写入，不能概括为零写入/零下载的幂等。

### 标题、目标目录与副本
- 同一文章改标题后仍使用已记录文件名，不自动改名。
- 改为不同文章目录时，在新目录分配路径并更新该文章映射；旧文件保留，不自动搬动或删除。
- “另存副本”保留原文件并分配新路径；该文章映射随后指向本次副本。
- 用户手工搬走/重命名文件后，程序不全库搜索：原映射路径缺失时按删除重建处理。

## 图片复用与仅 Markdown
普通全量保存**每次仍先下载图片，再算哈希**。只有媒体 ID 已记录、图片目标目录相同、下载内容哈希一致，且磁盘上文件实际存在并具有相同哈希时，才复用并跳过该图片磁盘写入。
- 图片删除后会补写。
- 内容变化或本地图片改动时，不按同名覆盖旧图片，而是分配不冲突路径并更新媒体映射；旧图片可能保留。
- 文件已从文章移除时，不自动清理旧附件或旧媒体清单。

“仅下载 Markdown”是本次同目录保存选项：
- 不下载或写入图片，不要求未使用的图片目录存在。
- Markdown 使用网站图片原 URL（网站相对地址转为绝对地址），不产生指向未下载本地附件的链接。
- 不删除已有图片，不清空旧媒体映射，不修改预设。
- 再次全量保存时恢复媒体下载、哈希校验与本地链接写入。没有媒体的文章同样不要求图片目录。

## 并发与失败边界
- 同页队列和同源浏览器 Web Locks 串行化此保存流程；缺少 Web Locks 的浏览器拒绝目录保存。
- 锁不能覆盖其它浏览器/来源或 Obsidian、文件管理器等外部应用。文件系统 API 没有原子 compare-and-swap，最后检查与写入之间仍有外部竞争窗口。
- 媒体、Markdown、清单**不是跨文件原子事务**。后续失败可能遗留新附件，或出现正文已写但清单写入失败；不承诺自动回滚或完全一次执行。
- 不删除用户原稿、旧附件或旧记录来“修复缓存”。不要手工删清单来绕过本地修改保护。
- 原生授权、应用登记以及真实 Obsidian 打开结果需在实际设备确认；目录标记存在并不等于应用已登记该仓库。
